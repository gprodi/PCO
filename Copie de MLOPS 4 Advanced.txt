notion sur les brokers
Un broker permet de gérer la communication asynchrone entre services, ce qui évite de bloquer l'application en attendant une réponse, permettant ainsi une exécution plus fluide et réactive.
Pour des développeurs d'applications en IA, l'utilisation d'un broker est cruciale pour découpler les processus, exécuter des tâches parallèles et ne pas bloquer l'application pendant des calculs lourds ou des traitements de données.

Apache Kafka - Rabbit MQ - Celery
Kafka :
Kafka est une plateforme de streaming distribuée conçue pour gérer un grand volume de messages en temps réel, permettant une communication hautement scalable entre services.
Celery :
Celery est un framework permettant d'exécuter des tâches asynchrones ou planifiées, souvent utilisé pour des traitements lourds en arrière-plan. Il utilise le broker RabbitMQ entre autre

C’est un peu comme une API, on déclare un app Celery et on utilise un décorateur nommé qui sera connu par l’API de fast_api.
Ici le prédicteur est bidon, il attend, normalement 5 secondes mais on dirait qu’il bug et ne trouve pas les 5 secondes à attendre.
Celery nomme les tâches en fonction de leur chemin, en forçant le nom on évite des problèmes. 
Dans l’api on appelle pas predict_task  mais on appelle predict_task.delay() car cela ajoute la tâche à la file d’attente.

import os
import time

from celery import Celery

# Configuration dynamique via Docker Compose (avec défaut)
BROKER_URL = os.getenv("CELERY_BROKER_URL", "redis://localhost:6379/0")
RESULT_BACKEND = os.getenv("CELERY_RESULT_BACKEND", "redis://localhost:6379/0")

app = Celery("ml_tasks", 
broker=BROKER_URL, 
backend=RESULT_BACKEND)

@app.task(name="predict_task")
def predict_task():
    # Simulation d'un modèle d'IA lourd
    processing_time = int(os.getenv("MODEL_LATENCY", "5"))
    time.sleep(processing_time)
    return {"status": "complete", "prediction": 42}

from celery.result import AsyncResult
from fastapi import FastAPI

from worker import predict_task

app = FastAPI()


@app.post("/predict")
def run_prediction():
    # On envoie la tâche au broker sans attendre
    job = predict_task.delay()
    return {"task_id": job.id}

Flower
Outil de monitoring en temps réel pour Celery, offrant une interface web pour surveiller l'exécution des tâches.
Permet de visualiser l'état des workers, d'annuler des tâches en cours et d'analyser les temps de réponse de vos modèles IA.
Il se connecte directement au Broker (Redis ou RabbitMQ) pour intercepter et afficher les événements du cluster Celery.
On Branche Flower sur le Broker.
