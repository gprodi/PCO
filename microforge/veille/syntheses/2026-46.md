## T2 — Outillage LLM local, CI et chaîne d'approvisionnement
### Node 20 retiré des runners GitHub : actions à migrer
- **Quoi** : GitHub a basculé le runtime par défaut des actions JavaScript sur Node 24 puis retiré
  Node 20 (septembre 2026) ; les actions qui le déclarent encore sont exécutées de force en Node 24.
  `gitleaks-action` v3 : « migrates the GitHub Actions runtime from Node 20 to Node 24. There are no
  changes to inputs, outputs, or behavior » ; la v2 « will stop working regardless of any opt-out flag ».
- **Sources** : journaux de notre CI (run 116 du 06/11, primaire, 7/7) ;
  [README gitleaks-action v3.0.0](https://github.com/gitleaks/gitleaks-action/tree/v3.0.0) (primaire,
  6/7) ; [changelog GitHub du 23/09/2026](https://github.blog/changelog/2026-09-23-node-20-is-no-longer-available-in-github-actions)
  (primaire, lu par extrait de recherche : à relire à la source).
- **Inventaire** (fichiers `action.yml` à l'empreinte épinglée) : les 14 actions JavaScript de nos
  workflows déclaraient `node20`.
- **Changements cassants lus** (README des versions retenues) : checkout v6 range les identifiants
  dans un fichier séparé (« No workflow changes required »), v7 refuse le code d'un fork pour
  `pull_request_target` et `workflow_run` (nous n'utilisons pas ces déclencheurs) ; setup-node v5 à v7
  : cache automatique et suppression d'un jeton factice avec `registry-url` (non utilisé) ;
  upload-artifact v7 : entrée `archive` (vraie par défaut, comportement inchangé) ; setup-uv v10 :
  mêmes entrées `enable-cache` et `python-version`.
- **Action (faite)** : `ci.yml`, `collecte.yml`, `docs.yml`, `veille.yml` passent à checkout v7.0.1
  (17/07), setup-node v7.1.0 (07/10), upload-artifact v7.0.2 (07/10), setup-uv v10.3.2 (22/10 ; la
  v10.3.3 du 28/10 a moins de 14 jours) et gitleaks-action v3.0.0 (30/05), épinglées par empreinte
  de commit. Test `tests/test_workflows.py` : toute action épinglée par empreinte complète avec sa
  version, plus aucune empreinte Node 20 dans ces quatre workflows.
- **Reste** : `cd.yml`, `pages.yml`, `model-cd.yml` (actions Docker, release-please, Pages,
  create-pull-request) ne tournent que sur `main` et `jeux-de-donnees.yml` relancerait un
  entraînement de plusieurs heures : à migrer et vérifier lors de la fusion de la PR #14. Les
  boilerplates du site de révision enseignent encore checkout v4.2.2 et setup-uv v6 : à mettre à jour.

- **Quoi** : code de bonnes pratiques sur la transparence des contenus générés publié le 10/06/2026

- **Sources** : [Commission — code de bonnes pratiques](https://digital-strategy.ec.europa.eu/en/policies/code-practice-ai-generated-content)

  le copilote rédige des réponses ; le code et le câblage générés viennent du moteur déterministe.
- **Action** : lire les lignes directrices à la source (exceptions « assistance à l'édition ») avant de
