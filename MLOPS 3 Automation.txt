Prefect
Le MLOps, ce n'est pas seulement emballer du code dans Docker. C'est s'assurer que les données coulent de manière fiable et que les modèles restent performants dans le temps. 
Prefect transforme les scripts Python en workflows robustes, capables de : 
s'auto-réparer (Retries)
se déclencher seuls (Scheduling) 
surveiller la santé de vos prédictions (Drifting).

 @flow (L'Orchestrateur) : le point d'entrée du pipeline.
name : Pour donner un nom clair dans l'interface.
log_prints=True : Capture tous les print() pour les afficher dans les logs Prefect.
description : Pour documenter ce que fait le flux.
Peut lancer plusieurs tâche

5

Décorateur Prefect
@task (L'Unité de Travail) : une étape spécifique du flow
retries : Nombre de tentatives en cas d'erreur.
retry_delay_seconds : Temps d'attente entre deux essais.
tags : Pour filtrer ou limiter la concurrence (ex: ["toto"]). Si toto =2 alors prefect pourra lancer jusqu’à deux jobs en parallèle.
cache_key_fn : Pour ne pas recalculer une étape si les données n'ont pas changé.
Une opération unitaire qui peut nécessiter les options des tâches.

exemple
@flow(name="Demo Concurrence", log_prints=True)
def pipeline_calcul():
    print("Envoi de 10 tâches à l'API ")

    futures = []
    # 1. On lance les tâches (file d'attente)
    for _ in range(10):
        fut = appeler_api.submit(a, b)
        futures.append(fut)

    # 2. attend que chaque tâche soit terminée
    for f in futures:
        f.result()

    print("Toutes les tâches sont terminées !")

Le déploiement
Pour un vrai déploiement on enlève les “serve” du code et on utilise la commande : prefect deploy  dans le terminal.
Cette commande : 
build les images (pré build par précaution)
push sur docker hub
donne les règles pour le pull de l’image
configure le worker

# 1. On build les images manuellement ou avec le CI/CD
docker build -t account/api-flow:latest .
docker push account/api-flow:latest

# 2. On lance le serveur
docker-compose up 

# 3. déploiement du flow (création du worker, connection au serveur et déploiement)
prefect work-pool create "docker-pool" --type docker
prefect config set PREFECT_API_URL="http://localhost:4200/api"
prefect deploy --all

# 4. On démarre le pool
prefect worker start --pool 'docker-pool'

Prefect.yaml
On peut avoir plusieurs déploiement depuis un seul prefect.yaml ici, la fonction mon_flow_calcul du fichier task.py du dossier flows
work_pool : pour séparer (par exemple si on a plusieurs serveur)
Il faut lui donner le nom de l’image et surtout lui donner la possibilité de communiquer en dehors du conteneur (hos)
parameters : des variables à transmettre
schedule : le schedule
14

deployments:
  - name: "calcul-final-v5"
    entrypoint: "flows/task.py:mon_flow_calcul"
    work_pool:
      name: "docker-pool"
      job_variables:
        image: devermyst/api-flow:latest
        env:
          PREFECT_API_URL: http://host.docker.internal:4200/api
    parameters:
      a: 10
      b: 20
    schedule:
      cron: "0 9 * * *"
